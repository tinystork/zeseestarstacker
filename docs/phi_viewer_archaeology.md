## 1. Boundary and product split

The scientific sources are read by the preview producers but are not mutated by them:

- Classic / non-Drizzle: `SeestarQueuedStacker._update_preview_sum_w()` reads copies of `cumulative_sum_memmap` and `cumulative_wht_memmap`, computes `SUM / WHT`, and delivers a preview tuple.
- Standard Drizzle: `SeestarQueuedStacker._update_preview_drizzle_accumulator()` calls `DrizzleAccumulator.finalize("divide")`, stacks the returned copies, and delivers a preview tuple.
- Final FITS is written in `_save_final_stack()` from the final scientific/raw-output path. The final PNG is separately generated by `_save_final_preview_png()` → `save_preview_image(data_after_postproc, ...)`.
- Neither the Qt preview renderer (`seestar/gui_qt/*`) nor the display controls call a FITS writer, PNG writer, SUM/WHT mutator, Drizzle accumulator mutator, registration code, or science reconstruction code.

The existing producer-isolation witness (`tests/test_preview_raw_linear_producer.py`) proves that the Classic SUM/WHT arrays and Drizzle accumulator arrays are unchanged by preview production.

### 2.2 Standard Drizzle preview

```text
DrizzleAccumulator[]
  │ QueueManager._update_preview_drizzle_accumulator() [engine worker]
  │ acc.finalize("divide") copies → HWC float32 raw_linear
  │ legacy display value: global p1/p99 map → clip [0,1]
  │ if needed: direct MAX_PREVIEW_SIDE_PX (1000) INTER_AREA resize
  │ then direct current factor 1..4 INTER_AREA resize
  └─ callback((legacy_normalized, raw_linear), PREV_SRC=Drizzle Accumulator, ...)
       │
       └─ identical Option-A Qt path above
```

The legacy `_update_preview_incremental_drizzle()` still contains a path that starts from `cumulative_drizzle_data`; it is not the current standard-Drizzle `refresh_preview()` route, which calls `_update_preview_drizzle_accumulator()` when the standard accumulator session is active. It remains an archaeology item for R2 instrumentation, not evidence that it drives the observed run.

### 2.3 Saved products (separate from live Qt preview)

```text
final scientific image / support state
  ├─ final FITS: `_save_final_stack()` → FITS HDU write
  └─ cosmetic normalized copy → `data_after_postproc`
       └─ final PNG: `_save_final_preview_png()` → `save_preview_image()`
```

The saved PNG has its own `seestar.tools.stretch` path. It does not call Qt `MainWindow`, `preview_analysis`, `preview_adjust`, or `render_view`. PHI must preserve that path unless direct evidence requires a separately justified change.

## 4. Resolution, cache, and thread map

### Resolution source integrity

For the active Classic path, every engine refresh reconstructs from the current SUM/WHT memmaps and resizes directly from the freshly reconstructed full-resolution source. For standard Drizzle, every refresh finalizes the current accumulator and directly resizes that new output. There is no code path in either active producer that downscales the immediately preceding 1/2 or 1/3 payload to make the next payload.

On the Qt side, an active run uses `_effective_preview_downsample_factor() == 1`: the engine-pushed geometry is displayed at its native pushed size. Thus M24 prevents a second Qt downsample of an already engine-downsampled active-run frame. Idle resolution cycling is a separate, local QImage-only view transform.

### Cache / object ownership

- Engine: each producer call allocates/copies its preview arrays.
- Qt Option-A: `_raw_linear`, `_pristine_float`, `_wb_only_float`, and `_preview_source` are distinct owned buffers. `QImage` construction ends in `.copy()`.
- Histogram: the coordinator retains at most one running and one replacement pending request. It reads, never mutates, the replaced-not-mutated WB-only buffer.
- View transforms: `render_view()` uses copies/scaled products; it does not mutate `_preview_source`.

### Asynchrony and remaining candidate

The Qt histogram has explicit latest-wins generation handling. The *preview payload* itself does not carry a monotonic producer sequence, requested-resolution factor, or source-buffer identity. `MainWindow._on_preview()` accepts every valid payload and replaces `_preview_source` unconditionally.

The engine processing thread may emit a normal preview while the Qt run-worker thread applies a resolution-control refresh. These are distinct emitting threads into the same Qt preview signal path. Therefore a stale payload replacing a newer-resolution payload is a credible **race hypothesis**, even though cumulative resampling is not present in the active producers. R2 must prove or rule it out with sequence/resolution/source instrumentation and an adversarial delivery witness.

## 5. Differential archaeology

### `67337a8` → `6e48257`

The viewer attempt changed only Qt preview-analysis/rendering and witnesses:

- `seestar/gui_qt/main_window.py`
- `seestar/gui_qt/preview_analysis.py`
- `seestar/gui_qt/preview_adjust.py`
- relevant tests, a real-data witness, and `docs/preview_highlight_integrity_archaeology.md`

It did **not** change `queue_manager.py`, FITS writing, saved PNG writing, SUM/WHT, Drizzle accumulation, registration, or reconstruction.

The useful independently verifiable portions were:

1. recognizing `map_raw_linear()` and `apply_wb_float()` as early clip sites;
2. retaining raw-linear data in the Option-A tuple rather than relying solely on a QImage;
3. keeping display operations separate from scientific buffers;
4. using a bounded histogram worker with stale-result rejection.

The attempt also changed semantics beyond the current PHI target: it made the histogram describe the final post-tone display buffer and introduced a new shoulder-based renderer. That is not accepted as a PHI solution merely because it was committed on the experiment branch. R2 evidence must decide the minimal needed semantic correction.

### `7aa07af` → `a331fa8`

This comparison contains the same viewer implementation plus closure/report artifacts. Its only unrelated source delta is line-ending normalization in `seestar/gui/settings.py`; it has no viewer behavior relevance. The closure commit is documentary evidence, not validation of the implementation.

## 7. R1 conclusion / R2 acceptance target

No scientific corruption evidence was found. The baseline contains direct, presentation-only premature clipping and an unclear preview-payload ordering contract. PHI-R2 must add debug-gated compact stage telemetry and deterministic synthetic/real witnesses before any behavior change.
